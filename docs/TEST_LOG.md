## 2026-11-20 · 副词/虚词泄漏测试

### 问题

担心"非常/稍微/特别"这类副词会被当成标签输出。

### 结果：零泄漏

| 输入 | 输出标签 | 副词泄漏 |
|---|---|---|
| 非常漂亮的花海，稍微有点亮的阳光 | flower field, bright, light | 无 |
| 她十分安静地坐着，略微低头 | quiet, peaceful, sitting, looking down | 无 |
| 极其精致的白裙，相当好看 | white dress | 无 |
| 她很开心地笑了，眼睛特别亮 | happy, big smile, smile | 无 |

有 AI / 无 AI 两种模式都测了，均无泄漏。

### 顺带发现

| 问题 | 说明 |
|---|---|
| `画面特别柔和，比较温暖的感觉` 输出为空 | 词库缺"柔和/温暖/感觉" |
| `不要太亮` → 负向得到 `bright` | 语义反了，应写 `过曝` |

### 结论

```
副词表不需要做：模型切词会剥离，词库也没有副词条目
真正缺的是形容词（柔和/温暖/精致/好看）
```

已补词：柔和、温暖、精致、好看、漂亮、明亮、阳光、开心、舒适、干净、通透、氛围感强。

## 2026-11-20 · 分段阈值实测（60 是怎么来的）

### 定义

| 项 | 定义 |
|---|---|
| "长句" | 输入文本超过 `SEG_LIMIT` 个字符（默认 60，`len()` 计数） |
| 切分单位 | 按 `，。；、！？` 切分句 |
| 打包上限 | 每段 ≤ `SEG_LIMIT` 字（贪心合并短句） |
| 超长单句 | 单句 > 上限时硬切 |
| 可调 | 环境变量 `PT_SEG_LIMIT` |

### 同一段 191 字文本，改阈值的效果

| 阈值 | 段数 | 段长分布 | 短语数 | 命中 | 未收录 | 耗时 |
|---|---|---|---|---|---|---|
| 40 | 5 | 40/40/36/37/34 | 18 | 14 | 7 | 10.4s |
| **60** | 4 | 54/52/55/27 | 27 | **18** | 12 | 4.4s |
| 80 | 3 | 73/78/38 | 17 | 15 | 5 | 3.5s |
| 120 | 2 | 118/72 | 20 | 17 | 4 | 3.0s |
| 不分段 | 1 | 191 | 11 | 11 | 0 | 1.6s |

### 结论

```
命中数（有效信息量）在 60 达峰：18 个（不分段只有 11）
但 60 的未收录也最多：切得细 → 碎片多（头顶/胸前/眼睛/长长）
40 反而变差：句子被拦腰截断，命中掉到 14，耗时 10.4s
```

**取舍**：60 = 召回最优；80 = 输出更干净。

原始数据：`docs/data/seglimit.log`

## 2026-11-20 · 长句拆分（自动分段）

### 动机

长文本时模型倾向"概括"，标签数不增反降；且否定词容易丢。

### 实现

```
SEG_LIMIT = 60（环境变量 PT_SEG_LIMIT 可改）
按 ，。；、！？ 切句 → 贪心打包到 ≤60 字 → 逐块调用模型 → 合并结果
超过 60 字的单句硬切
info 会显示【分段】N 段
```

配套改动：

- 送给模型的仍是**原文**（保留英文语境，避免中文语法被切断）
- 模型输出只采信**含中文**的短语，纯英文交给透传
- 过滤单字碎片（`微` / `站` / `长长`）

### 结果（同一批 10 个样本）

| 样本 | 原始 | 只加分段 | 最终版 |
|---|---|---|---|
| T05（75 字） | 10 标签 / 4 未收录 | 12 / 2 | **12 / 0** |
| T06（191 字） | 6 / 8 | 22 / 13 | **22 / 12** |
| T07（143 字） | 10 / 8 | 16 / 10 | **16 / 9** |
| T08（403 字） | 9 / 12 | 29 / 12 | **29 / 12** |
| T09（251 字重复） | 8 / 0 | 9 / 0 | 8 / 0 |
| T10（中英混合） | 12 / 0 | 11 / 7 | **9 / 0** |
| **合计标签** | 87 | — | **142（+63%）** |
| **合计耗时** | ~20s | — | ~38s |

### 代价

- 长文本耗时约翻倍（2s → 5-8s）
- 短文本（< 60 字）不触发分段，速度不变

### 剩余未收录性质

```
身体部位：头顶、胸前、眼睛、肩膀、双手
组合描述：山脉轮廓、云层交织在一起、温暖偏粉紫、柔和温暖
动作细节：风吹起、垂下、挡住、几缕
```

> 属于长尾表达，补词边际收益递减，暂停。

原始数据：`docs/data/longtext_after_segmentation.log`

## 2026-11-20 · 非中文透传改造

### 背景

发现"只要句子含一个汉字，整句（含英文、数字、权重、`<lora:>`）都会进模型"，
导致：

- `abc` 被模型判成负向
- `(masterpiece:1.2)` 被标点切碎成 `masterpiece:1.2)`
- `不要 watermark` 里的 watermark 被"自动补回"又加进正向

### 改动（全部在节点 Python 层，模型未动）

| 函数 | 层 | 改动 |
|---|---|---|
| `split_verbatim()` | 预处理（新增） | 逐字符扫描，按分句把中文与非中文分开；只有 `，,。；;、！？!?` 是分句符，`.` `:` `()` 不算 |
| `translate()` | 后处理 | 合并透传片段（正向/负向按分句否定判断） |
| 自动补回 | 后处理 | 已在负向中的 token 不再补回正向 |

### 验证

| 输入 | 期望 | 结果 |
|---|---|---|
| 花海 abc | abc 原样正向 | ✅ |
| 少女站在花海 `<lora:lilyww_v1:0.8>` | LoRA 标签完整 | ✅ |
| 少女微笑, (masterpiece:1.2), 1girl | 权重括号不被切 | ✅ |
| 不要 watermark，樱花 | 樱花正向，watermark 负向 | ✅ |
| a girl in flower field, smile | 整句透传 | ✅ |

### 未解决

- `去掉文字和签名` 这类并列否定，模型仍会整条丢弃（待做拆分）
- 长短语匹配（`双手交叠在胸前`）模糊匹配覆盖不到

原始输出：本轮未单独落盘，见节点 info 输出。

## 2026-11-20 · 模型对英文的处理能力

### 方法

直接调用 `ask_model()`，输入 12 个中英混合句子，检查英文片段是被保留、被翻译还是被丢弃。

### 结果：保留 8 / 12

**保留良好**

| 输入 | 模型输出 | 评价 |
|---|---|---|
| 少女站在 flower field 微笑 | `flower field` | 短语完整 |
| masterpiece, 少女微笑 | `masterpiece` | ✅ |
| **不要 watermark，樱花** | 负: `watermark` | ✅ **英文否定判断正确** |
| 不要 blurry, 不要 watermark, 樱花 | 负: `blurry, watermark` | ✅ 两个都对 |
| a girl, 微笑 | `girl, 微笑` | ✅ |
| a girl in flower field，微笑 | `girl, flower field, 微笑` | ✅ |
| soft lighting，少女站在花海 | `soft lighting` | ✅ |
| girl standing in 花海 | `girl, standing, 花海` | 短语被拆，但内容在 |

**丢词（都发生在“标签式”英文上）**

| 输入 | 丢失内容 |
|---|---|
| 花海 abc | `abc` |
| 1girl, 少女微笑, **best quality** | `best quality` |
| 少女 `<lora:lilyww:0.8>` 微笑 | **整个 LoRA 标签** |
| 少女微笑 `(masterpiece:1.2)` | **整个权重** |

### 规律

```
模型保留：像自然语言的英文短语
模型丢弃：带符号的（<> () :）、无意义短 token、部分质量词
模型从不把英文翻译成中文
```

### 透传兜底验证（节点层）

| 输入 | 节点最终正向 |
|---|---|
| 少女 `<lora:lilyww:0.8>` 微笑 (masterpiece:1.2), best quality | 全部保留（`<lora:...>`、`(masterpiece:1.2)`、`best quality` 都在） |
| 1girl, 少女微笑, best quality | `1girl` + `best quality` 都在 |
| 不要 watermark，樱花 | 樱花正向、watermark 负向 |

### 结论

> 英文可以进模型让它理解语境，但**输出必须以透传为准，不能采信模型**。
> 模型对英文否定的判断与我们的分句规则一致，互为兜底。

### 关键发现

1. **耗时与长度无关**：4 字和 403 字都是 1-3 秒。
2. **标签数不增反降**：38 字出 11 个，191 字只出 6 个（模型倾向概括）。

| 文本 | 整段命中率 | 分段命中率 |
|---|---|---|
| T06 | 27% → 补词后 100% | 37% → 79% |
| T08 | 40% → 95% | 49% → 77% |

### 归因（重要）

```
细节丢失 = 10% 模型概括 + 20% 短语过长匹配不上 + 70% 词库缺词
```

**补词库是主要手段，换模型只解决那 10%。**
